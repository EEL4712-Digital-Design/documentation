# KV260 Cluster Headnode

The headnode manages the cluster of Kria KV260 boards used in this course.

## Connect to the headnode via SSH

Connect with your GatorLink username and password:

```bash
ssh <ufl_username>@ece-b312-recon2.ad.ufl.edu
```

You may also use
[Visual Studio Code with the **Remote - SSH** extension]({% link remote-access/ece-linux-server-access.md %}#optional-visual-studio-code-remote-access)
or another SSH client.

## Prepare the application binary/executable and bitstream

The scheduler needs only two files from your account on the headnode:

- a **64-bit AArch64 (ARM 64-bit architecture) executable** containing your compiled software
- the `.bin` bitstream generated by Vivado

You do not need to transfer the complete lab directory or Vivado project unless
you intend to build or edit those files on the headnode.

### Option 1: Build on the headnode

To compile the application on `ece-b312-recon2`, first make its software
sources and `Makefile` available there. You can clone or update your Git
repository, or transfer only the lab's software source directory. Then change
to that directory and build:

```bash
cd <software_directory>
make
```

The Vivado project is not needed on the headnode. Transfer its generated `.bin`
file separately if it is not already present on the headnode.

### Option 2: Build locally or on an ECE Linux server

You may instead compile the application on your own computer or on an
[ECE Linux server]({% link remote-access/ece-linux-server-access.md %}). Because
the KV260 runs 64-bit Arm Linux, you must **cross-compile for AArch64**; a
native x86-64 executable will not run on the boards.

The course Makefiles use `aarch64-linux-gnu-g++` by default. When using the
toolchain installed with Vivado 2025.2.1, start by initializing your environment. 

On a generic Linux installation, here is an example. Your actual path may be different:

```bash
source /opt/Xilinx/2025.2.1/Vivado/settings64.sh
```

On an ECE Linux server, you do this by
[sourcing the provided `enable` script]({% link remote-access/ece-linux-server-access.md %}#configuring-the-course-software-environment).

Once your environment is setup, enter the directory that contains your software's
source code, and then run `make` to compile it:

```bash
cd <software_directory>
make
```

### Transfer the completed files

If you built elsewhere, transfer the completed AArch64 executable and `.bin`
file to the headnode. You can drag the two files into a VS Code Remote-SSH
window, use a graphical SCP client such as WinSCP, or run:

```bash
scp ./<application> ./<bitstream>.bin <ufl_username>@ece-b312-recon2.ad.ufl.edu:~
```

This simply transfers the files to your user directory (`~`) on the headnode. If you want to be more organized, you can create a directory hierarchy first, e.g., `~/labs/lab2` instead of just `~`.

## Submit a job

Submit the application and the Vivado-generated `.bin` file. The scheduler
will queue the job, assign an available KV260, and stream the application's
output to your terminal:

```bash
kv-submit -s ./<application> -b ./<bitstream>.bin
```

If the application takes command-line arguments, place them after `--`:

```bash
kv-submit -s ./<application> -b ./<bitstream>.bin -- <argument1> <argument2>
```
